# Benchmark entry and capabilities

Host prerequisites: Python 3.11+ and PyYAML (`scripts/requirements.txt`), plus the
selected native Harness/Benchmark tools. Check them before any paid call; npm
installation alone does not install host Python dependencies.

Start from the user's one sentence, for example `使用 GDPevo 子集进行 RSI`.
You are the main Penguin and own every stage, worker, result and recovery. Do not
wait for Codex to fill an internal id or advance a stage. No helper here launches
a model, grades a task, chooses a Skill or runs the experiment for you.

1. Resolve `PROJECT_DIR` from Environment App Data Dir. Read the public experiment
   settings the user named, else `PROJECT_DIR/evo-experiment.json` when present.
   The runtime is the explicitly configured experiment pair and thinking level,
   else your Environment's actual pair and level. Never read a credential file
   or silently choose another model. Collect missing model, authorization and
   experiment choices into one question before paid work. Reuse authorization
   already supplied for this scope; historical unrelated budgets do not apply.
2. Read the installed package, not an assumed repository layout. Run the installed
   `scripts/resources.py` with one request in your Session scratchpad:

   ```json
   {"project":"ABS_PROJECT_DIR","prompt":"使用 GDPevo CRM 进行 RSI，沿用本项目已有实验配置。","output":"ABS_FRESH_ENTRY.json"}
   ```

   A `dataset` name or absolute native package path may replace `prompt`.
   GDPevo shorthand such as `024` or `GDPevo 024` is resolved against the
   source manifest task_group_id after acquisition, never by guessing Case IDs.
   Existing `PROJECT_DIR/evo-experiment.json` supplies public runtime, budget,
   authorization, held-out package and deployment settings. Explicit request
   fields override those settings. If runtime is absent there, provide your
   Environment's actual provider/model/thinking values in this request. Keys
   and `.project_config.toml` are never read by this helper.

   It selects the Project package, follows each native Case's declared Task
   source, automatically fetches/caches the official repository, resolves the
   branch/tag to one actual commit and records its tree/inventory digest. It
   never executes Markdown shell code or converts a dataset. GDPevo and Sec A–E
   retain their official tasks, adapter and scoring implementation. Supplied
   `resource_checkouts` can reuse an existing matching checkout; the experiment
   still uses its own clean, detached, commit-addressed cached copy.
3. Read the entry receipt and its saved plan. The receipt names the installed
   protocol helper and provides the complete `prepare-config` request skeleton;
   merge the existing public deployment settings, then use that request. Internal
   IDs, rosters, source paths and the plan hash are generated by the helper.
   A repeated identical entry uses the frozen plan without fetching a newer ref.
   Changed task/source/Project files fail reconciliation instead of silently
   replacing an experiment. A generic GDPevo request without a selected domain
   returns all matching domains and one semantic selection question; each
   controller binds one domain. Budget remains total unless per-benchmark scope
   was explicitly authorized. Train once; test each frozen State three times by default. Preserve an explicit
   separately frozen repetition count; do not retrain between test repetitions.
4. Check `project_packages`, `missing_inputs`, `environment` and
   `capability_blockers` before paid calls. Missing tools are preparation work
   for you: install the official runtime using its documented entry, preserving
   the frozen model/version. Resolve native State/CLI/bundle paths from the
   running installation and existing experiment settings; do not ask the user
   to assemble internal IDs or commands. Only user choices, credentials or
   permissions you cannot derive belong in the one consolidated question.
   Complete task image/network preflight before workers; executable availability
   alone is not Docker readiness. Reuse matching verified deployment artifacts;
   a missing source bundle is built once with the installed
   `scripts/runtime/make_source_bundle.sh`, then reused across the experiment.

   A source checkout is not proof of a matching Project import. Preserve existing
   package files and scoreboards. For a fresh local package path, use the native
   Benchmark import/placement API; for stale existing packages, obtain replacement
   authorization or choose a fresh experiment Project. The contract compares
   complete Case files and effective manifest values, excluding native runtime
   state and import timestamps. Never expose rubric bytes to learning roles.
5. Inspect `capability_blockers` before dispatch. A blocked backend is an explicit
   unsupported capability, not a missing model setting or a passing preflight.
   Follow the selected capability below. Preserve the `.6` algorithm: fixed
   Solver, one attempt, negative-feedback reflection in that original Session,
   no successful-task candidates, one batch Evolver, ADD/MERGE/REVISE/SKIP,
   general descriptions plus current-context/topic bodies, and a 16000-byte
   complete package. Keep training/test materials separate. A backend's extra
   retry or candidate-selection facilities do not change these settings.

## Continuous live-feedback adapter

`gdpevo-continuous-v2` reads `tasks/task_group.yaml`, package statements and
`task.toml`. Its explicit mappings separate source Benchmark id, experiment-local
Benchmark id, native Case id, Harbor task name and internal training member id.
There is one training Case/container containing the full ordered member list.
Do not dispatch one Harbor task per member. Paths, port, feedback route, output
locations, roster and task timeouts come from the adapter, not the learning code.

Use the installed `scripts/runtime/protocol.py`. The official Benchmark checkout
contains task resources only; it needs no Evo branch or experiment scripts.
Its `prepare-config` operation accepts the saved ready `plan`, `plan_sha256`,
returned contract name, installed `evo_tool`, repo/Project and deployment settings. It prepares fresh Target/Trainer ids and
experiment-local Benchmark ids automatically. `source_benchmark_ids` and source
commit identify the verified imported packages; private runtime bindings never
overwrite a user's existing package or scoreboard. Resolve initialization,
bundle/runtime and zero-model environment checks using native tools and the
existing experiment deployment settings. Do not let a missing setting cause
silent adapter defaults. Freeze the resulting complete config before dispatch.

Follow `control.md` and `group-training.md` with the adapter's member roster and
paths replacing historical examples. Configure the native controller with the
prepared `protocol_helper`; then prepare/register each native worker and call
`run_subagent` yourself. The evaluator runs one Harbor training task. Its native
training root calls sequential original Solvers and one Evolver. Verify export,
publish native snapshots, and finish H0 then final full matrices through the
unchanged shared evaluation protocol. Wait for actual Harbor completion and
cleanup; worker return alone is insufficient. Keep costs pending conservatively.

## Native Workspace cases

Use a distinct train/test roster and the same initialized frozen Target settings.
Use `workspace.py` prepare-profile with the ready plan path/hash to freeze both
rosters, runtime, budget, initialized H0 State and export policy. If it returns
`ready:false`, initialize the proposed Target with the native State tools and
the frozen settings, then prepare the profile; do not dispatch a Solver yet.
Pass the saved profile path/hash, returned Case id, `split:train`, one attempt id
and a fresh prompt output path to `prepare-solver`. It stages the public files
and returns their exact paths plus the native call; do not hand-build a grant.
Both preparation and feedback verify this same frozen profile, H0 file map and
actual native dispatch parameters. Native subagents inherit the parent's
actual Workspace; they do not accept a per-call cwd. Stage only the training
Case's public statement files in a fresh subdirectory of that Workspace and use
absolute assigned paths. This is a declared staging adaptation, not a claim of
per-case OS filesystem isolation. Each Solver still has a fresh native Session.
Delegate a Solver with native `run_subagent` and the fixed runtime. Its original
prompt includes the common learning principles and **In-session reflection**
section from the unchanged `.6` roles.md, public inputs, answer path and the
`evo_workspace_task` grant used by `scripts/workspace.py`. The Solver first solves
and returns its frozen answer; do not create a second solving execution.

A separate native evaluator grades that **existing training execution** against
its own private rubric, returns the standard one-cell protocol, and never sends
the rubric or a suggested answer. `workspace.py` `prepare-feedback` verifies the
actual worker reply and original Solver binding, snapshots answer and feedback,
and prepares one exact native `input_subagent` call. Invoke that returned call
on the original child. Success observes feedback without candidates; failure
reflects in the same history. Keep the candidate format, evidence and uncertainty
requirements of `.6`. Only its own candidate draft and fixed digest request may
be written after feedback. Do not query task data, edit the answer or regrade.

After the original child returns, use `workspace.py` `capture` with the complete
terminal trace. It verifies original-Session feedback/order, answer immutability
and reflection, then uses the ordinary `capture-evaluation` context format.
Concatenate candidates without edits, call one independent Evolver with `.6`
guidance and all authorized training contexts, and use the existing compiler. Use workspace.py prepare-export with the frozen
profile path/hash; its request fixes description-only storage and the total
package budget without relying on a manually repeated argument. Then use native
State/snapshot and evaluation operations. Account for the original Solver’s cumulative Session usage once, including
reflection; its earlier solve usage is not an additional charge. No fresh Reflector,
training retest or score gate is introduced. Capture after reflection, never
relax a previously captured trace hash. General and topic loading is unchanged.

## Other Harbor cases

`native-cases-v1` discovers their real task paths and launch settings and supports
frozen State export, evaluation and result accounting. A stock Harbor verifier
grades only after the original Solver exits and its container closes. It has no
live original-Solver feedback channel: **full Evo learning is unsupported until
a declared adapter supplies and verifies that channel**. Report this capability
limit before paid learning; do not relabel trace reconstruction as live reflection
or substitute another algorithm. Ordinary Workspace continuation does not imply
container Session continuation. An explicit offline-replay experiment remains a
different, labeled protocol.

## Complete and report

Finish the frozen roster × runs, H0 then final, without changing a Skill from
test feedback. Reconcile existing Session/job/operation records before recovery.
Preserve scores, failed attempts and unknown cost liabilities; a format repair
does not rerun a Target. Keep the native scoreboard schema. Report actual
coverage, task-level scores, costs and whether each backend has paid end-to-end,
zero-model native, synthetic or unsupported validation. A capability declaration
or offline pass does not prove a real autonomous run or a score gain.

## Historical package verification

Recognize only the exact current Readers and the two Readers retained by .6
commit `1b56cb777e515564fd6b2059818ae165242bb560`. Validate every original file,
manifest hash, native method identity, full read plan and aggregate byte budget.
Old plans have one known absolute container State root; a read-plan request can
map that exact root to the explicitly supplied State after fingerprint checks.
It returns calls without editing the old Reader, package or State.

Read-only compilation verification rebuilds bytes in the reference package's
recognized format in memory, then compares every byte. It does not re-export
or rewrite historical Skills. Keep the original method/benchmark/configuration,
paired scores, fees and audit conclusion; a new compatibility report has its own
verifier version and scope. Parsing a package is not proof of a complete old run.
Unknown Reader text, earlier selector/single-file formats, absent raw evidence or
changed hashes require a specific unsupported/missing-evidence result. Never
rewrite old data to obtain a pass.
